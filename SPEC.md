## Full spec (verbatim intent)
1. Overview: personal, lightweight, Obsidian-inspired Markdown notes PWA for iPhone. Single user. No native app, no Apple Dev account, no server/backend/db/cloud functions operated by Joe (the free relay above is the agreed exception), no paid services, nothing extra on the phone, no git on phone. GitHub = remote source of truth + history. All notes stored locally, offline-capable. Small maintainable codebase.
2. Goals: fast mobile-first editor; simple file/folder browser; native-feeling checklists; full local copy of repo; automatic GitHub sync; conflict detection + safe merging; offline editing; persistence across restarts; simple install/deploy; clean minimal expandable UI. Don't reproduce all of Obsidian.
3. Tech: static client-side PWA; vanilla JS ES modules, HTML, CSS; IndexedDB; Service Worker for app shell; Web App Manifest; GitHub REST API (contents/trees/blobs/git data as appropriate; simplest reliable strategy); Device Flow. No React/Vue/large frameworks; small markdown parser/editor lib OK if it materially helps. Deployable static to GitHub Pages. Local-first client, not a full git implementation, but preserve files, dirs, meaningful commit history, reliable sync.
4. Mobile UX: iPhone first. 4.1 Main editor: compact top bar, note title, file-browser control, minimal overflow menu, comfortable editing area, small sync status indicator, optional bottom toolbar. No permanent sidebars/dashboards. Editor fills height and adjusts for iOS keyboard; respect safe areas. 4.2 File browser as separate view/overlay: hierarchical folders/files, expand/collapse, nested nav, one-tap open, quick return to current note, new note, new folder, rename/move/delete with confirmation for destructive actions, search by filename or content. Remember + restore last-opened note. Responsive with thousands of notes. 4.3 Nav: open browser, search/quick switcher, create note, back, secondary actions, optional tabs only if simple. 4.4 Visual: restrained, Obsidian-mobile-inspired. Identity "Core Sample": app icon = isometric geological core sample with visible strata that subtly evoke stacked notebook pages. Earthy understated palette. Light + dark, follow system. Visually quiet; content dominates.
5. Markdown: headings, paragraphs/line breaks, bold/italic, bulleted/numbered lists, checklists, links, inline + fenced code, blockquotes, hr, basic tables if practical. 5.1 Checklists high priority: - [ ] / - [x]; tap to toggle in rendered/interactive view; updates source and marks modified; no cursor jump, no keyboard pop, no lost place. 5.2 Modes: source editing + rendered preview, easy switch; live preview only if lightweight and clearly better; default dependable. 5.3 Reliability: save locally as user types, never depend on network to save, debounce without risking loss, preserve cursor/selection, don't replace whole doc unnecessarily, handle large notes, preserve Unicode/emoji/newlines/formatting, warn before discarding unsaved changes if possible.
6. Local storage: complete local copy in IndexedDB: notes, folder hierarchy, other text files, content+encoding, last known remote SHA, local modified status, last sync time, pending ops, conflict/merge metadata, repo+branch config. Offline open/search/edit/create after initial download. Migratable schema. 6.1 Request persistent storage; handle IDB errors + quota; never silently delete local repo; never auto-overwrite local changes on refresh; export/backup; explain clearing Safari website data erases local data. SW caches app shell only.
7. GitHub: one repo + one branch. Setup: authenticate, select repo, choose branch, choose notes root dir, initial download, start. Device flow, no client secret. Minimum permissions. Store auth locally; never put tokens in source, repo files, logs, URLs, errors. Handle expiration/revocation/reauth/401s. Explain client-side credential limits. 7.1: repo metadata, enumerate, initial download, fetch individual files, create/update/rename/move/delete, sync branch, preserve meaningful history. Don't redownload whole repo during navigation; incremental after setup.
8. Sync (core): feels like obsidian-git; no manual Sync button needed. 8.1 Launch: show last note + local repo immediately, check branch in background, reconcile, update UI, restore last note; no blocking loading screen. 8.2 Opening note: show local immediately, check remote change via metadata/cached index, fetch if needed, reconcile, update safely without discarding active edit. 8.3 Edit: persist locally, mark dirty, debounce ~2–5s (configurable), queue sync, check remote before write, merge, push, update metadata, show status. Batch changes; avoid tiny commits. 8.4 Periodic check ~60s while open; also on foreground, network return, navigating away from edited note, page hidden, close/suspend best-effort. Don't promise background sync on iOS; reconcile on next launch.
9. Conflicts: never blindly overwrite changed remote. Keep base/local/remote; three-way merge. Local-only -> push; remote-only -> pull; non-overlapping -> auto-merge; identical -> once; overlapping -> preserve both (conflict markers or conflict copy). Conflict UI to inspect diffs, keep both, resolve manually. Data preservation over clean doc. 9.1 Use SHAs/git object ids; on stale SHA/branch moved, refresh + retry reconcile; limited retries + visible error.
10. History: readable logical commits ("Updated meeting notes", "Created a new note", "Synchronized several local changes"); simple consistent messages. Hide git concepts in main UI. Multi-file changes in single commit via Trees/Commits API. Never push to a different branch; no force-push or history rewrite.
11. Status indicator: Synced, Syncing, Offline, Changes pending, Conflict, Authentication required, Sync failed. Subtle but persistent. On failure: keep local changes + pending ops, exponential backoff, respect rate limits, explain auth/permission errors, don't spam same error, manual Retry. Never show synced until remote write succeeded and metadata updated.
12. Search filenames + content locally offline. Create/rename/move/delete/search/recent notes. Preserve relative paths/links on move/rename where practical. Markdown links + basic internal (wikilink) navigation; no graph. Deletions explicit in sync so local delete can't erase unrelated remote update.
13. Offline: cached shell launches; open, edit, toggle checklists, create/rename, search, queue changes; reconcile on reconnect. Distinguish local save vs remote sync. Never lose an edit due to network.
14. Security: no analytics/telemetry/ads/external sync service/unneeded third-party calls; no hardcoded creds; no tokens in git; no sensitive content in logs; min permissions; clear logout/disconnect. Explain static-PWA credential isolation limits. Disconnect GitHub without deleting notes; separate confirmed "erase local repo".
15. Deploy: clear dir structure, manifest, SW, icons, GitHub Pages deploy guide, iPhone install guide, GitHub auth config guide (incl. Cloudflare Worker relay + OAuth App device flow), troubleshooting. Install = deploy static files, open HTTPS URL in Safari, Share -> Add to Home Screen, open, connect GitHub + pick repo. No Xcode/TestFlight/App Store.
16. Tests (mock GitHub, no real creds): markdown parse/render, checklist toggling + source, local persistence + restore, offline editing, create/rename/move/delete, initial sync, incremental remote updates, local-only, remote-only, non-overlapping 3-way merge, overlapping conflicts, stale SHA, failed push + retry, auth expiration/revocation, recovery after restart, preservation of unsynced changes. Manual verification on a real iPhone before done (install, keyboard, persistence, foreground sync, recovery after suspend).
17. Process: work incrementally. Before coding: inspect repo conventions, pick smallest architecture, write DECISIONS.md, create AGENTS.md (project coding/testing rules), prioritized plan. Stages: 1 Basic PWA (shell, mobile layout, manifest+SW, local editor, IndexedDB, create/open notes, checklists). 2 Repo & file mgmt (browser, rename/move/delete, search, local repo model, import/export/backup). 3 GitHub connection (auth, repo/branch select, initial download, SHA tracking, basic push/pull). 4 Auto sync (debounced saves, incremental checks, fg/bg transitions, retry queue, status). 5 Conflicts (3-way merge, overlap detection, keep both, conflict UI, recovery tests). 6 Polish & deploy (iPhone UI, offline tests, real-iPhone test, docs, verify no backend). END OF EACH STAGE: run tests, review for unnecessary complexity, update docs, summarize changes/tests/limits/next stage, and STOP for human review. Do not silently proceed through stages.
18. Done when Joe can: install from Safari; open from home screen without browser chrome; auth once and stay connected across restarts; download repo + browse; open notes instantly from local; edit + tap checklists; close/switch without losing changes; auto-sync when active/online; reconcile with desktop edits; work offline and sync later; recover from conflicts without loss; meaningful GitHub history; no custom server (beyond agreed free relay), native install, paid service, or Apple Dev account.
Final priority: reliability and simplicity over feature count; smallest dependable version; never sacrifice data safety for seamless-looking UI.
