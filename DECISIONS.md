# Decisions

Core Sample is a static PWA. This is the architecture for Stages 1–6. Stage 1 implements only what [PLAN.md](PLAN.md) assigns to it. Later stages should extend this shape, not replace it.

## Stack

Vanilla JavaScript ES modules, HTML, and CSS. No framework and no bundler. IndexedDB is the database. The service worker caches the app shell and nothing else.

Markdown is hand-rolled. Checklist taps have to flip a specific `[ ]` / `[x]` in the source, and the renderer and the toggler have to agree on which boxes count. A library would not make that mapping safer.

The editor is the one exception to "no library". Live Preview (v30) needs a text surface that keeps the caret, selection, undo and the iOS keyboard while it hides and shows Markdown around the caret. A hand-made `contenteditable` cannot do that without rebuilding an editor, and a `<textarea>` cannot show rendered text at all. CodeMirror 6 is the smallest editor that does it and is what Obsidian itself uses. Only `@codemirror/state`, `view`, `language`, `commands` and `@lezer/markdown` are bundled, once, by `npm run editor` into `app/vendor/codemirror.js` (about 308 KB, 101 KB gzipped). There is no CDN. The service worker caches the file with the rest of the shell, so the editor works offline. `@codemirror/lang-markdown` is not used because it pulls in the HTML, CSS and JavaScript languages. The research is in [docs/live-preview.md](docs/live-preview.md).

## Why this shape

The product is one offline client. The page calls `api.github.com` directly for repository reads and writes. A Cloudflare Worker exists only because GitHub's device-code endpoints have no CORS. Notes never live in this repo. There is no application server.

## Layout

- `app/` is the site uploaded to GitHub Pages. URLs are relative, so the same files work at `/core-sample/` and at a local `/`.
- `app/js/` keeps parsing, storage, and save policy out of the DOM so `node --test` can import them.
- `test/` holds the tests. `fake-indexeddb` and Playwright's WebKit are devDependencies.
- `scripts/render-icons.py` builds the PNGs from `app/icons/source/core-sample-icon-source-v2.jpg`.
- `worker/` is the device-flow relay. GitHub Pages publishes `app/` only. Joe deploys the Worker himself.

## Storage

Database name `core-sample`, version 3.

`files`, keyed by repo-relative path (`Welcome.md`, later `folder/note.md`):

- `path`, `content`, `kind` (`markdown`; later `text` or `binary`), `encoding`, `createdAt`, `updatedAt`

Folders are not records. The tree is the set of paths, plus a `folders` meta list so an empty folder can exist before it has a note. Rename and move change paths. They do not copy the note into a second store.

A trashed note stays in `files` with `trashedAt` set. The text is unchanged. Restore clears `trashedAt`. Empty Trash is a separate confirmed action and is the only one that deletes note records. Old records without `trashedAt` are live notes.

`meta`, keyed by string. Keys: `lastOpened`, `folders`, `recent`, `expanded`, `seeded`, the GitHub connection keys (`githubToken`, `githubClientId`, `githubRelay`, `githubRepo`, `githubBranch`, `githubRoot`, `githubLogin`), `githubTokenMeta` (last-4 fingerprint, saved time, source, poll seq), `githubPollSeq`, `githubAuthLog` (last 20 auth events), `storagePersistent` (whether `navigator.storage.persist()` was granted), `githubVaultIndex` (the path list, blob shas, and attachment folder used to resolve images), `githubResolvedEmbeds` (note plus embed text, and the vault path, each pointing at the resolved path), and `imagePrefetch` (the last prefetch counts). `editorMode` (the old Source and Preview choice) is deleted on launch from v30; nothing reads it.

`images`, keyed by repository plus path, holds one cached attachment: `data` (an ArrayBuffer), `bytes`, `type`, and `sha` when the git blob sha is known. Version 2 creates this store when it is missing and does not delete `files` or `meta`. An older record may still hold a `blob` until the next successful read copies those bytes into `data` and rewrites the record without the Blob. A blob that a note still embeds is never deleted. Only a blob no note still points at may be removed. A failed read is not a delete.

`ops`, keyed by note path, is the pending sync queue (version 3). Adding it does not delete `files`, `meta`, or `images`. A failed push leaves the operation here and leaves the note text in `files`. Erase local copy clears the queue. Disconnect does not.

A file may also carry `baseSha` (the blob SHA last known to match GitHub) and `conflict` (both sides changed). A conflict copy is a separate file with `conflictCopy: true` and is not pushed.

Later versions add fields and stores. Do not invent a parallel place to keep a note.

- Stage 3 file fields: `remoteSha` (blob SHA from the last successful push or pull) and `dirty` (local edits since that SHA). Old records stay valid if these are missing.
- Stage 4: `baseSha`, `conflict`, and the `ops` store. A conflict copy is a separate file with `conflictCopy: true` and is not pushed.
- Dot paths: any path with a segment that starts with `.` (`.obsidian/`, `.trash/`, `.git*`, `.github/`) belongs to Obsidian or Git. It is never listed as a note or attachment, never uploaded, never deleted, and never made into a conflict. Trees are always written with `base_tree`, and their entries never name a dot path, so those files keep their exact blob and mode. Note and folder names starting with a dot are refused. Dot-path notes an older version already downloaded stay in IndexedDB untouched and are hidden.
- Stage 5: `conflictAt`, `conflictReason`, `conflictRemote`, `conflictRemoteSha`, and `conflictBase` record why a note is conflicted and the GitHub text, so the resolve screen works offline. A delete or rename is an `ops` row with `kind`. A remote delete is sent only when the blob SHA still matches `baseSha`. A clean remote deletion removes the local note only when `baseSha` equals `remoteSha`, the file's blob in the last-synced tree (`lastBlobs` on the sync cursor) equals that base, and the new head descends from that last-synced head (the cursor's `headSha`; the note's own `syncedCommit` only when the cursor has no `lastBlobs`). Descent is walked through every parent of every commit with the same Git Data commit read, at most 200 commits, so a merge commit whose first parent never had the note cannot remove it, and a long Obsidian history since the note was last pulled does not matter. When GitHub cannot answer a commit read, nothing is removed and the cursor is not moved; the sync retries with backoff. Commit dates are never compared, so a computer with a slow clock cannot leave a stale copy. Anything else that GitHub no longer lists becomes a Conflict with reason `deleted`; nothing is dropped silently. A note that has never been synced is uploaded only when the user created it in the app (`origin: 'user'`). Welcome is `origin: 'app'` and `localOnly`, and leftover `(conflict …)` / `(backup …)` copies are never uploaded. Restoring a note after its delete has synced marks it user-created and dirty with no base so it uploads again. Non-overlapping edits auto-merge. Overlapping edits open the resolve screen. A rejected ref update (422 or 409) or a head that moved before the write means another client pushed first, usually Obsidian Git's `vault backup` or its merge commit. The sync waits (400 ms doubling to at most 4 s, with jitter) and runs the whole pass again on the new head: each note is merged three ways against its base, the tree is rebuilt with `base_tree` set to the new head's tree, and the commit has that head as its only parent. Only an overlapping edit to the same note becomes a Conflict. After four retries the queue stays pending and the normal backoff retries later; a race alone never shows Sync failed and never writes a conflict copy. `conflictRemoteAt` is the GitHub commit time shown as "As of". `syncedAt` and `syncedCommit` record the last confirmed head. `conflictCopyPath` records the `(conflict …)` copy written for that note. A copy matches a note only by that path, by the path derived from `conflictAt`, or by the exact basename `<name> (conflict YYYY-MM-DD HHmm).md` in the same folder when exactly one fits. A note recorded before v26 has no GitHub text; the resolve screen fetches GitHub's current blob for that path when online, uses the matched copy offline, and otherwise turns off Keep GitHub and Keep both and says why. Resolve refuses to save an empty or missing body unless both sides are empty. Loading GitHub's text for such a note gives up after 15 seconds (an `AbortController` plus a timer, so a request that ignores the abort cannot hang the screen). With no GitHub text the screen shows the phone's text as plain lines and says why (offline, too slow, or not loaded) with Try again, instead of diffing against an empty side. Resolve shows Syncing… on its button and disables the choices until the plan and its sync finish.

The save status is only local: Saving…, Saved on this device, or a save failure. It is read by VoiceOver but drawn under the title only for a failure or a link that went nowhere. The sync status is separate: Synced, Syncing, Offline, Changes pending, Conflict, Authentication required, or Sync failed. Settings always shows it, with the failure detail and Retry. The note screen shows it only for a conflict, a conflict copy, Authentication required or Sync failed (`syncAlert` in `github-sync.js`). Synced is shown only after a poll or a ref update has been confirmed. Push and pull still report on their own line in Settings.

## Save policy

The open note in memory is the working copy. IndexedDB is updated 400ms after the last keystroke, and immediately on note switch, checklist toggle, `visibilitychange` to hidden, and `pagehide`.

The flush starts the IndexedDB transaction synchronously so iOS can finish it while the page is suspending. A failed write leaves the text on screen and shows an error. Nothing is deleted to recover. `navigator.storage.persist()` is requested at launch, and whether it was granted is stored and shown in Settings in plain words. Clearing Safari website data for this app still erases IndexedDB; the welcome note says so.

Remote sync uses its own 3 second debounce. That clock must never be what saves the local copy.

## Markdown and checklists

`checklist.js` owns task parsing and fenced-code rules. The renderer uses those same helpers, so a box inside a code fence is neither a button nor a toggle target.

Toggling replaces one mark character (` ` or `x` / `X`). The string length does not change, so the editor's selection stays put. Leading spaces and tabs stay byte for byte, including when the same words appear on more than one line: the tap toggles the box at that position in the text. The control is a non-editable `role="checkbox"` island inside the editor with a 44pt hit area. It is handled on `touchend` with `preventDefault` and does not focus the editor, so the caret does not move and the keyboard stays down. The toggle saves at once.

Nested lists follow the source indent. A tab is four columns, the same step as four spaces. Two spaces is a shallower step, and a tab plus four spaces is one step deeper than the tab alone. A task is a checkbox with no bullet; its text sits beside the box, and a wrapped line stays under the text. Child items are real nested lists, so they indent from that item whether the parent is a task, a bullet, or a number. A line that is only more indented, and not itself an item, stays inside that item. An image embed on that line stays an image there, including one indented two tabs under a nested task. `- ## Heading` is a heading inside the list item, and the tasks under it stay nested there.

Wikilinks: `[[target]]`, `[[target|alias]]`, `[[target#heading]]`, `[[target#heading|alias]]`. A tap on the rendered link resolves against local notes: full path, otherwise a unique filename, case-insensitive. One match opens that note and scrolls to the heading when there is one. No match creates a note with that name and opens it, which is the Obsidian behavior. More than one match does not guess. The control is a non-editable `span.wikilink` island in the editor, not an `<a href="#...">`. In an installed iOS app a fragment link with no matching id does nothing, and iOS does not reliably treat that tap as an in-app action. A long press puts the caret inside the link to edit it, as in Obsidian.

External `http:`, `https:`, and `mailto:` links open through a temporary plain anchor with `rel="noopener"` and no `target`, clicked once. iOS standalone ignores `target="_blank"` and `window.open` (the new browsing context is dropped, so the tap looks dead). A normal navigation is what that WebKit opens in its in-app Safari view. `javascript:` is not linked. Relative markdown links stay inside the app and are resolved like wikilinks, so removing `target="_blank"` cannot navigate the installed app away from itself.

Image embeds follow Obsidian. `![[img.png]]`, `![[img.png|300]]`, and `![[img.png|300x200]]` are images, as is `![alt](path)`. A link resolves to an exact vault path, then a path relative to the note, then a unique basename anywhere in the vault, then the file closest to the note when several share that basename (attachment-folder path wins a tie). The Custom Attachment Location v0.0.9 default `./assets/${filename}` is used for new images and for that tie-break. Core Sample does not write `.obsidian/app.json`. `${filename}` / `${noteFileName}` is the note's file name without its extension, `./` is relative to the note's parent, and a leading slash is still from the vault root. When the file list does not already name the image, those likely paths are requested directly and the first 200 wins. The recursive tree is fetched once and shared by every image in flight. A hit is remembered for that link. A later 404 drops the remembered path and the lookup runs again. The list is saved only after a 200 tree, with the time and the tree sha. An error never saves an empty list. A saved list is used again for about 10 minutes, then rebuilt when it is older than that, when its sha changes, or when a lookup misses. `Not found in vault` is used only when a fresh, complete list has no match. Each path segment is percent-encoded once, so a space is `%20` and `/` stays a separator. `https` images and `data:image/*` URIs render directly. Other image files are fetched on first view from the GitHub contents API with `Accept: application/vnd.github.raw`. The token is only an Authorization header. A JSON contents body is decoded from its base64 `content` field. Bytes that are not an image are not cached. Bytes that are an image are cached in IndexedDB as an ArrayBuffer (database version 2 adds an `images` store and does not delete notes). The page builds a new Blob from that copy and shows it with an object URL, revoked when another note opens. A view does not write the image record. WebKit invalidates a Blob it just read from IndexedDB if that same record is stored again, for the rest of the session, and the previous shell treated that throw as a corrupt file and deleted it. A failed read is tried once in a new transaction and the record is kept either way. Online, a later download overwrites that key. Offline, the chip says the image is not available yet. An older Blob record is copied to an ArrayBuffer on the next successful read. Every lookup reads that saved map and the blob store before any network request, including when the file list is older than its refresh window. Sign-in, download, and pull then walk every note in the background, resolve both `![[...]]` and `![](...)`, and store the blobs. A blob already stored with the same git sha is skipped. The work does not block the editor. A failure is left unstored and tried on the next sync. `navigator.storage.persist()` is requested at launch and again when that save starts. A failed cache read or write still shows the bytes already in memory. A failed download is not stored, and tapping the placeholder tries again. Offline, an image that was never saved says `Not downloaded yet (offline)` and does not say `Sign in again`. The placeholder otherwise says one reason: `Not found in vault`, `Sign in again`, `No access to repo`, `Couldn't reach GitHub (HTTP <status>)`, `Couldn't reach GitHub (offline)`, `Unsupported format`, or `Couldn't display`. That text never includes a token, a header, or a URL. On launch, a saved file list with no paths or no fetch time is deleted. The image cache stays. Settings says who is signed in, or that the sign-in or the repo needs attention, and never shows the token. The database is version 3. Version 2 added the image store and version 3 adds the sync queue. Neither upgrade deletes notes or cached images, so a cached image remains readable. SVG is an `<img>` pointed at that blob, never markup in the page. HEIC is a named placeholder because Safari will not paint it in an `<img>`. An image that has not finished decoding is left in place; only an error that is still broken on the next frame becomes `Couldn't display`. That chip does not delete the stored bytes. Tapping a loaded image opens a full-screen viewer on a black backdrop: it zooms out of the thumbnail, pinches around the fingers up to 4× fit, pans with a rubber-band at the edges, double-taps to 2.5×, and swipes down to dismiss. Several images in the note swipe sideways, and the neighbors come from the same blob cache. The viewer is `aria-modal` only while it is open. Its photo element is given its own object URL, created after that element is in the document, from a copy of the bytes. The editor keeps the URL it is already showing, and closing the viewer does not revoke that URL. The viewport meta tag is unchanged. iOS has ignored `user-scalable=no` since iOS 10, so the viewer sets `touch-action: none` and, only while it is open, cancels Safari's `gesturestart`, `gesturechange`, and `gestureend` events. That keeps a pinch from zooming the installed app. Those listeners stay off the document while the note is showing. A standing non-passive touch listener is what made iOS stop painting inline images. Nothing in this path writes to the repository.

## App shell and subpath

Manifest `start_url` and `scope` are `./`, resolved against the manifest URL. On Pages that is `/core-sample/`. The file is `manifest.json` so GitHub Pages serves it as `application/json`, which browsers accept. The service worker is registered as `./sw.js`; its scope is that directory.

Cache name and the build id in Settings → About are the same string, `core-sample-shell-v37` (`APP_BUILD` in `app/js/version.js`, `CACHE` in `app/sw.js`). Bump both when a shell file changes. The test fails if they diverge.

The installed app stayed on the old shell because the v1 worker returned cached `index.html` and scripts whenever they were in the cache (`if (cached) return cached` in that worker's `fromCacheOrNetwork`). The open document keeps running the JavaScript it already loaded. v1 never called `registration.update()`, never set `updateViaCache: 'none'`, and had no `controllerchange` reload. iOS standalone also checks for a new `sw.js` less often than a Safari tab. The phone therefore kept executing the cached v1 bundle — the one whose preview still said the target note doesn't exist — after the site was already serving the fix. v2 was still cache-first, so the next bump would stall the same way.

Navigation, `index.html`, `sw.js`, and app JS/CSS are network-first. Those fetches use `cache: 'no-cache'`, so the HTTP cache cannot answer with the previous shell. If the network fails, the worker uses its cache, and a navigation falls back to cached `index.html`. Icons and the manifest stay cache-first. Install precaches with `cache: 'no-cache'`, then `skipWaiting`. Activate deletes older caches, calls `clients.claim()`, then `client.navigate()` so a page still running an older bundle loads this shell. That navigation fires `pagehide`, which flushes the open note.

The page registers with `{ updateViaCache: 'none' }`, calls `registration.update()` on launch and when the document becomes visible, and on `controllerchange` flushes the open note and reloads. The first install does not reload from that listener. If navigating to the current URL is rejected, the worker loads the same page once with `?shell=` set to the build id, and the page removes that query with `history.replaceState` so it does not stick. Auto-reload, not a banner: a banner is easy to miss, and the last failure was a status line that did not get the new code onto the phone.

Cross-origin requests and anything that is not the shell are ignored. Note text is never cached. After an update, check the build id in Settings → About and reload Core Sample from the home screen. Removing the Home Screen icon deletes that web app's data on iOS, including IndexedDB notes, so do not remove it to pick up a new shell.

## iPhone layout

`viewport-fit=cover` and `black-translucent` let the page draw under the status bar, from physical y=0. On Joe's standalone iPhone, innerHeight, `100%`, `100dvh`, and `100svh` were 797 while outerHeight, screen.height, `100vh`, and `100lvh` were 844. The 47px difference is the top safe inset, not the keyboard. v8 pinned `#app` with `position: fixed` and a JS `--app-h` of 844. The box was that tall, and WebKit still clipped and ignored touches in the bottom 47px, so the footer build id sat off-screen. v10 sizes `html` to `100lvh` only in `display-mode: standalone`, and `body` and `#app` fill that parent with `height: 100%`. html and body are not fixed and do not clip overflow. Scroll stays inside the editor, the sidebar list, and Settings. The keyboard overlap is still `innerHeight - visualViewport.height - offsetTop`. While the keyboard is down the shell is that CSS height. While it is up, `html` is pinned to `visualViewport.offsetTop + visualViewport.height` (`--shell-h`, class `is-keyboard`) so the format toolbar sits flush on the visual viewport's bottom — the form accessory bar if iOS draws one, otherwise the keys. The accessory itself cannot be hidden from a Safari tab or a Home Screen PWA; see [docs/live-preview.md](docs/live-preview.md). The shell shrinks from the CSS height only when the overlap is greater than 80px. If innerHeight stays short of the screen, scroll content is padded by `max(safe-bottom, oriented screen − innerHeight)` so the last controls stay inside the touchable area. `screen.width` and `screen.height` do not swap; portrait uses the long side and landscape the short side. A browser tab does not add that gap. The build id is in Settings → About, and tapping it toggles `#layout-debug`. The overlay shows `100lvh`, `100vh`, `100dvh`, and `100svh` from hidden probes, plus `clientHeight` and the html and body rects. html and body both paint `--bg` in light and dark, so a strip WebKit will not lay out still matches the app. Header padding clears the status bar. The sidebar and Settings stay absolute inside the frame. Light and dark follow `prefers-color-scheme`. The palette is paper, clay, and shale. `theme-color` meta tags match that paper. The manifest colors are the light paper (`#f3eee6`). iOS reads the status-bar style and the splash when the icon is added and does not refresh them later.

## GitHub connection

Stage 3 signs in with GitHub's device flow. The browser cannot call `https://github.com/login/device/code` or `https://github.com/login/oauth/access_token` directly, so `worker/` forwards only those two URLs and only for `https://joecoffey.me`. The Worker has no client secret and does not log the body. `wrangler.toml` has no secrets. Joe deploys it; this repo does not.

The client id and the relay origin are typed into Settings → GitHub (the gear at the bottom of the sidebar). They start empty. The token is written only to IndexedDB. A pending device flow is stored there too (`deviceCode`, `userCode`, `interval`, `expiresAt`) so signing in can resume after iOS suspends or reloads the installed app. An expired leftover flow is cleared without asking to connect again. The device code is not shown, logged, or put in a URL. The user code is shown on screen. Repo, branch, and notes-root calls go to `api.github.com` with the token in an `Authorization` header, never in the URL. Signed-in state comes from the saved token. Settings shows that login, and Push and Pull for the open note, before the access check returns. The check runs at most once every 10 minutes, with an 8 second timeout, and opening Settings does not start another one. Only Disconnect, or a 401 from `GET /user`, changes that state. A 401 on any other call, a 403, a 404, a network error, or a timeout leaves the token and the repo settings in place and shows that error. A `/user` 401 keeps them too and shows a Sign in again button. That button starts the device flow without clearing the repo, branch, or root. The new token is saved only when GitHub returns one. Cancel keeps the old token. Connect stays hidden while a token is saved.

A device code is used for one token, once. When the token arrives, it is saved and the pending flow is cleared in one IndexedDB transaction, before the login lookup or any other network call. Before v29 the code stayed saved until after `GET /user` answered, so a reload, a service worker update, or iOS ending the app in that gap made the next launch poll the used code again. GitHub does not document what a second token request for a used code returns. If it regenerates the grant (the security log shows `oauth_access.regenerate`), and that answer is lost or written out of order, the phone keeps a value that no longer works. A code that has returned a token is also never polled again by the same page, and Check now, visibility, pageshow, and launch share one poll loop. Each token poll takes a numbered claim in IndexedDB before it is sent (`githubPollSeq`). A later complete from an earlier poll cannot write that first token back. A second page cannot start another poll while the claim is held. Later writes fill in only the login, and only while the same token is still saved, so a slow lookup cannot put an older token back. The relay forwards each request once and never retries.

A 401 from `GET /user` is asked again twice, after 0.7 and 2 seconds, before Settings shows Sign in again or sync shows Authentication required. When it holds, the phone records the last sign-in failure in IndexedDB (`githubAuthFailure`): the time, the endpoint (`GET /user` or `POST /login/oauth/access_token`), the HTTP status, GitHub's message or device-flow error, and the last 4 characters of the token that was sent. The record never holds the token or the device code. Settings shows it under the storage line as Last sign-in problem, with `sent …xxxx, saved …xxxx` so a later failure can be matched to GitHub's security log (which shows the last 8). The sign-in section also shows the saved token's last 4, when it was written, and how (device flow, already on this phone, and so on). A ring of the last 20 auth events (`githubAuthLog`: token saved, token read at startup, 401, recheck result, sign-out) stays on the phone with timestamps, last-4 fingerprints, and the code path. Copy sign-in log puts that ring on the clipboard. The log, the sheet, and error text never include a full token, a device code, or a user code.

OAuth Apps have no contents-only scope. `repo` is the smallest scope that can read and write a private repository. `public_repo` cannot see a private repo. The scope does not add `workflow`, `admin`, or `delete_repo`. The app lists a tree, reads Markdown and attachment bytes, and creates or updates Markdown files and attachments. An unchanged attachment move reuses GitHub's existing blob sha instead of uploading bytes. It does not force-push, and it writes only to the repo and branch saved in Settings.

The intended repository is the private vault named in SPEC.md. The app does not fill that name in. The notes folder defaults to the repo root when the field is blank. Paths on the phone are relative to that folder.

Download stores each Markdown file's blob SHA. If the phone already has notes, the download waits for an explicit choice: keep local notes alongside, or export a backup and then confirm replace. A SHA mismatch on push keeps the phone's copy. Pull of a note with local edits keeps the phone's copy unless the text is already identical. Disconnect deletes the token and the repo, branch, and root settings. It leaves the client id, the relay URL, and the notes. Erase local copy is a separate confirmation and does not remove the token.

Automatic sync uses its own 3 second debounce, not the 400ms local save. Dirty notes are one commit via the Git Data API (blobs, tree, commit, then `PATCH /git/refs/heads/<branch>` with `force: false`). Reads stay on `GET /git/ref/heads/<branch>`. The ref is read again immediately before that write, and a moved head is not written. A 422 or 409 on the update reads the branch again: if the dirty notes are unchanged there, a new commit is made on that head; if they changed, both copies stay. A failed ref update keeps the commit object and retries the update instead of creating another one for the same parent and text. The open app polls about every 60 seconds and also syncs when it becomes visible, when the network returns, and on page hide. There is no background sync. The next launch reconciles. Every sync request, body included, has a limit: 15 seconds, or 60 seconds for a blob download. The request is aborted, and the limit holds even when a fetch ignores the abort. A timeout keeps the notes and the queue, shows Changes pending (Offline when the network is down), and retries with backoff. It is never Sync failed. A run where no request starts or settles for 90 seconds is let go so the next poll can run, because before v29 one request that never answered left the status on Syncing until the app was reopened. Retries use exponential backoff with jitter, and a spent rate limit waits for `retry-after` or `x-ratelimit-reset`. A 401 from any call except `GET /user` does not sign out. A 401 from `GET /user` shows Authentication required and keeps the token and the queue. A missing or unexpected branch shows Sync failed and does not create or switch branches. When both sides changed since `baseSha`, or GitHub removed a note this phone still has, the local note stays and the other side is saved as `name (conflict YYYY-MM-DD HHmm).md` in the device's local time. That copy is not pushed. A remote deletion has no bytes, so the copy says the file is gone and the local note is kept. A clean note that has never been synced is pushed only if the user created it. Welcome, leftover conflict copies, and backup copies are not pushed, including when a v24 profile upgrades. After a successful commit the cursor stores that commit's tree so a rename's old path is not pulled back. An unchanged binary rename or move puts the existing blob sha in the new tree entry, deletes the old path in the same commit, and moves any cached bytes to the new key; it does not look up or re-upload bytes. A binary that cannot be resolved is left pending with an honest error and does not hold the rest of the commit. Leftover conflict copies keep the status tappable (`Synced · N conflict copies`) and Dismiss moves them to Trash. Overlapping merge is Stage 5. Do not commit vault contents.

## Testing

`npm test` runs `node --test`. Persistence tests use `fake-indexeddb` and a unique database name per test. WebKit tests run the app in Playwright with the iPhone 13 profile and save screenshots to `/tmp/core-sample-shots` (or `$CONFLICT_SHOTS`). The Live Preview and sidebar tests block the service worker: its first activate navigates every window onto the new shell, which can replace the page mid-test. Playwright WebKit refuses `new Touch()`, so swipes are dispatched with `document.createTouch` and `createTouchList`. Keyboard, Add to Home Screen, and standalone launch are checked on an iPhone.

## Rename, move, and links

The path is the identity. A rename or move rewrites the path, then rewrites links that resolved to that note. A path-style wikilink (`[[folder/note]]`) is pointed at the new path. A bare wikilink (`[[note]]`) is left alone when the file name is unchanged and still unique. A markdown link is rewritten when the relative path would otherwise break. Aliases and heading fragments in links stay. Links inside fenced or inline code are not touched, and an ambiguous name is not guessed. The open note is flushed before the path change. Note text is otherwise left byte for byte; a rename does not rewrite the first heading. The list, Recent, search, and the editor title show the filename without `.md`. A second line may show a short snippet of the body.

## Live Preview editor

From v30 there is one editing surface, as in Obsidian's Live Preview. There is no Source or Preview switch. Markdown is rendered in place, and the syntax of the element under the caret shows so it can be edited. Headings, quotes and horizontal rules reveal per line. Bold, italic, strikethrough, highlight, inline code and links reveal per span. A fenced code block reveals its fences while the caret is inside it. Bullets and checkboxes stay drawn unless the selection touches the marker. With the keyboard down (editor not focused) nothing is revealed. `live-rules.js` turns the editor state into a plain list of decorations and is unit tested without a DOM. Wikilinks and images are found by the same scanners `markdown.js` uses, so the rules agree with the old renderer about what is a link or an image.

Rendering never changes the text. The editor splits lines only on `\n`, so `\r\n` endings, tabs and trailing spaces round-trip byte for byte, and the 400 ms save, flush on hide, sync and conflicts read the same string. A heading keeps its font size with the caret on it, so revealing `#` does not move the lines below. Text uses the iOS body text style (Dynamic Type) and never drops under 16px. The editor is read-only until the last note has loaded at launch, so nothing typed in that moment is replaced. Images are drawn by the host with the same `embeds.js` and `images.js` code, one load per image link per open note, shared by redraws as the caret moves. Only the viewport is drawn, so a 3,000-line note scrolls without drawing every line.

The format toolbar is a rounded pill above the iOS keyboard while the editor is focused. With the keyboard up it has no bottom margin and the shell height is the visual viewport's bottom, so it sits flush on the accessory bar. Each button is a CodeMirror transaction from `format.js` (wrap, toggle, or insert). `pointerdown` is cancelled so the keyboard stays up. Hide keyboard is the only control that blurs. Enter continues lists and quotes through `list-continue.js`; Tab and the indent buttons nest and unnest. Bytes outside the touched lines stay identical, including CRLF.

v36 Live Preview adds rendered GFM tables with a cell editor, Obsidian callouts, `$…$` / `$$…$$` math as MathML (a small offline TeX subset; no KaTeX, no CDN), `![[note]]` embeds (heading and `^block` targets), a Properties panel for frontmatter, token colors in a few fence languages, and heading fold. Fold state is stored in IndexedDB meta `editorFolds` keyed by note path and heading key (`h2:title`), the same local-meta pattern as `expanded` folders. Image embeds are unchanged.

Math that the subset cannot parse stays visible as the original TeX. Fence colors cover js/ts, json, python, css, html/xml, bash, yaml, markdown, and sql; anything else stays plain. Note embeds cap at 4,000 characters and never recurse. A missing or ambiguous embed says so in the box and does not create a note.

Left out: Dataview LIST, TABLE, CALENDAR, dataviewjs, `FROM [[link]]`, and unknown functions are not run; those blocks stay as source plus "Not supported in Core Sample yet". Footnotes, comments, mermaid, PDF/audio/video embeds, tag chips, and HTML-as-HTML are still out.

A ` ```dataview ` TASK query is a Live Preview widget. `tasks.js` parses vault task lines (any list marker, nested, tabs or spaces, any status character). `task-index.js` builds an in-memory index from IndexedDB once, then updates only paths that change. Conflict copies, backup copies, and other leftover local copies are left out of the index. `dql.js` runs a small DQL subset: `TASK`, `FROM` (`"folder"`, `#tag`, `and`/`or`/`-`), `WHERE` (`completed`, `!completed`, `fullyCompleted`, `contains(text, "...")`, `text`, `tags`, `file.name`, `file.path`, `==`/`!=`, `&&`/`||`/`!`), `SORT` (`file.name`, `text`, `completed`, asc/desc), `GROUP BY file` (the default presentation), and `LIMIT`. Query time is local. Checking a result flips one status character in the source note through the existing save path and never rewrites the query note. Anything outside the subset renders the raw block plus "Not supported in Core Sample yet".

## Navigation and Settings

From v30 the notes live in a left sidebar like Obsidian's on iPhone. The note screen is the round panel button, the note title, and the note. A small flag at the top right appears only for a conflict, a conflict copy, a sign-in problem, or a failed sync. It is a 10px circle inside a 44×44 transparent hit area, vertically centered with the sidebar button. Failed sync and Authentication required paint as `--danger`. A conflict or leftover copy paints as `--accent` so pending-looking leftovers are not an error. Synced, Syncing, Offline, and Changes pending never show on the note. Tapping it opens Settings scrolled to Sync or GitHub. A conflict or leftover copy also opens the conflict list, which is the problem UI for those states.

The sidebar covers 85% of the width (at most 420px) and dims the note behind it. It opens from the panel button or a swipe right that starts within 28px of the left edge (after the safe area). It closes with a swipe left, a tap on the dimmed strip, Escape, or picking a note. Opening it blurs the editor so the keyboard goes down. The swipe follows the finger and settles open past a third of the panel (closed below two thirds when closing) or in the direction of a quick flick. It locks only onto drags that are clearly sideways, so vertical scrolling is untouched. It gives way to a long press (text selection) and to a drag that starts with text selected (a selection handle). Its listeners are passive and never call `preventDefault`, because a standing non-passive touch listener once stopped iOS painting inline images. In a Safari tab with history, iOS's own back swipe starts at the same edge and wins. The app keeps one history entry, and the installed home-screen app has no back swipe, so the two do not meet in normal use. The rules are in `drawer-gesture.js` and are unit tested.

The sidebar holds new note and new folder, then the Search field at the top of the panel (Aa and search options sit next to it), the file tree with Recent, Notes and Trash (name only, no per-row Edit), and a pinned footer: the vault name (the repo name, or Core Sample when not connected) with `<N> files, <M> folders`, and the gear. Tapping new note creates an empty `Untitled.md` (then `Untitled 1`, `Untitled 2`, … filling gaps) in the vault root, opens it, and closes the drawer. There is no name prompt and no starter heading. A folder's New note uses the same empty Untitled sequence in that folder. Tapping Search swaps the tree for results and keeps the field at the top, clear of the iOS keyboard. Aa match-case and Search note text are reachable while searching. Cancel or an empty field on blur restores the tree. A search with no hits says No matches found. Rename, move and delete live on a long-press (or right-click) menu on the row. File and folder counts follow the GitHub vault when the saved tree is present: every non-dot file, including attachments, and the folders that hold them. Without that tree they count local files that are not Trash, ignored, Welcome-from-the-app, or conflict/backup copies.

The gear opens Settings and closes the sidebar. Done returns to the note. The vault name is a label, not a button (there is one vault). Settings holds Sync (status, failure detail, Retry, Conflicts), GitHub (sign-in, Last sign-in problem, repo, download, Push and Pull for the open note, Disconnect, Erase local copy), Backup (one Export backup, and import, with the same add and replace confirmations), and About (the build id). When signed in, Client id, Relay URL and Save sit behind an Advanced disclosure. The small flag at the top right of the note is a 44pt transparent target with a 10px circle so a long status string cannot stretch it into a pill; the words stay in the DOM for VoiceOver and the tests. The sidebar and Settings follow the system light or dark setting. In dark mode the sidebar and Settings use Obsidian's near-black (`#1e1e1e`) with rounded 44pt controls.

Wrapped list and task lines hang under their text: `--list-hang` is the source indent in `ch`, `--list-marker` is the checkbox or bullet, and the wrap continues under the words. After Keep GitHub, the leftover "Move copy to Trash?" prompt always names this resolve's copy, even if an earlier prompt was left unanswered.

## Browser, search, and backup

The sidebar is the browser: nested folders, expand and collapse, recent notes, and search across file names and note text. Search skips Trash. Nothing in the browser is a second copy of a note.

Export writes one JSON file (`format: core-sample-backup`, version 1) containing every note, including trashed text, plus folders, the last opened path, and recent paths. Backups made before v30 may also carry an `editorMode`; import ignores it. Import parses that file or refuses it. Add keeps every note already on the device; a path that already has different text is stored beside it as `Name (imported).md`. Replace is a separate confirmation and is the only import that removes notes. On iPhone the export uses the share sheet when the browser allows a file share, and otherwise a download link with no `target`.

## Left out of Stage 4

Three-way merge, overlap markers, and a screen to resolve a conflict. A conflict stays put, with both copies on the phone, until that stage.
